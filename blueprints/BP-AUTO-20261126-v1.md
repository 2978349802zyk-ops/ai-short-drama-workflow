# BP-AUTO-20261126-v1 半自动：蓝图自动发现建卡，额度内自动跑

- 日期：2026-11-26 CST
- 决策：用户选半自动。目标：新蓝图推到仓库后，Hermes 自动发现、自动建卡、自动估算，额度内自动放行跑完并推回报告；超限、大方案、高风险停下等用户。用户不再逐条复制粘贴触发。
- 前提：同步 clone 自动拉取已跑通（inspect_tick.py + cron 7d225dc62bec，do_fetch=True）；判产漏洞按 BP-302-CONT-v4 先修好再启用自动放行。

## 蓝图元数据约定（以后每份新蓝图都带）

每份 BP 文件头部加一段机器可读元数据，监视器只认这一段：

- `auto_run: true/false`（false = 只发现不自动跑，等用户）
- `budget_tokens: 数字`（本蓝图总上限）
- `executor: 角色`（如 cc-python / cc-pm；禁止把 cc-review 当执行者）
- `output: 仓库相对路径`（如 reports/RPT-XXX.md，唯一产出）
- `risk: normal/high`（high = 大方案/公开推送/大额度/改分工流程，永远不自动放行）

没有元数据的旧蓝图一律按 auto_run=false 处理，只记录不执行。

## 第一步：建监视器（先 dry-run，不自动放行）

- 在 inspect_tick.py 的 repo-flow 扫描里加蓝图发现：扫同步 clone `blueprints/BP-*.md`，用 `.state/flow_state.json` 记录已处理清单（文件名 + 文件 sha），没处理过的才算新蓝图。幂等键 = 文件名 + sha，同一蓝图绝不重复建卡。
- 首次启用时，把现有全部 BP（含 BP-302-CONT v1-v4、BP-ROLES、BP-AUTOPULL、BP-SYNC、BP-TEST 和本 BP-AUTO）登记为已处理基线，不自动执行任何一份；BP-302-CONT-v4 继续按手动触发跑。
- dry-run 模式：发现新蓝图只写日志和 .state，不建卡、不调模型。先用一份测试蓝图验证：能发现、能解析元数据、重复扫描不重复登记。
- 解析失败、元数据缺失、output 路径不合法：一律只记录并停下该蓝图，不猜、不补。

## 第二步：自动建卡 + 自动估算（仍不自动放行）

- dry-run 验证通过后，监视器对 auto_run=true 且 risk=normal 的新蓝图：按元数据建一张 blocked 卡（卡体带 `## 文件域` + `## 产出文件` 绝对路径，指向同步 clone），assignee 用元数据 executor。
- 建卡后调 ikun 估算一次；估算本身的固定开销要计入回报。估算 > budget_tokens：卡保持 blocked，写 .state 记录并停下等用户，不放行。
- 估算在上限内：先只记录“可放行”，等第三步开关打开才真放行。

## 第三步：额度内自动放行（开关默认关，验证后开）

- 加一个显式开关（如 AUTO_RELEASE_ENABLED，默认 False）。打开后：估算在上限内、risk=normal、auto_run=true 的卡自动 unblock 并用 kanban_auto_dispatch.py --once 派发，只派这一张。
- 派发后靠现有巡检盯产出：声明产出文件存在且非空、且新判产规则判 produced，才算完成；完成后只提交元数据 output 那一个文件并正常 push。push 被拒只允许同步 clone 内 fetch+rebase 该提交，冲突 abort 停下，禁止 force push。
- 返工超 3 轮、卡超时、产出为空、实际消耗明显超上限：停下该蓝图，写 .state 记录，不再自动重试。

## 通知与记录

- 每份蓝图的处理状态写 `.state/flow_state.json`：discovered / card_created / estimated / released / done / stopped + 原因。日常正常不打扰用户。
- 关键事件才通知（沿用已有偏好）：自动拉取冲突/分叉、返工超 3 轮、正式任务完成或失败、巡检停了、估算超限停下。通知通道未定前，先只写 .state 和报告文件，不自选通道乱发。

## 验证顺序（每步过了才下一步）

1. dry-run 发现测试蓝图，重复扫描不重复登记。
2. 自动建 blocked 卡 + 估算，卡不放行，人工核对卡体解析正确。
3. 打开自动放行开关，用一份低风险测试蓝图（只写一个小报告文件）跑通全程：发现→建卡→估算→放行→产出→push。
4. 三步都过，写 `reports/RPT-AUTO-20261126-v1.md` 推回仓库并停下汇报。BP-302-CONT-v4 不走自动流程，仍手动。

## 禁止

- risk=high、auto_run=false、无元数据的蓝图不自动建卡/放行。
- 不把 cc-review 当执行者；不让同一角色既产出又审查自己的产出。
- 不改生产仓库，不碰 config.env / engine.py / 桌面会话，不贴密钥值。
- 不生成图片/视频，不调用 SenMuse（除非某份蓝图元数据明确写了且 risk 规则允许）。
- 判产漏洞（BP-302-CONT-v4 第一步）没修好前，不打开自动放行开关。

## 停下条件

监视器解析/建卡/估算任一步报错且原因不明；同一蓝图重复建卡；自动放行后产出为空或判产异常；.state 记录与看板状态矛盾；同步 clone 脏/分叉。任一发生，关自动放行开关，写明证据并停下。

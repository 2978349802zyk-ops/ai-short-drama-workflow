# Muse 提示词优化与自检框架（已搭好并实测）

日期：2026-11-19
状态：**框架已完成在线 52/0、离线 48/0 自检通过；按用户要求，本轮未生成新视频**

## 一、要解决的问题

用户反馈：`走廊的灯一盏接一盏熄灭`，Muse 生成的视频完全不按提示词来。

根因拆成三块：
1. **提示词不适合视频模型**：递进动作在一次 5 秒生成里无法表达。
2. **以前只看"文件生成成功"**：落盘、尺寸、时长合格就算过，没检查内容对不对。
3. **失败后没有反馈闭环**：跑偏了也不知道偏在哪。

## 二、七层结构

| 层 | 脚本 | 作用 |
| --- | --- | --- |
| ① 递进动作自动拆镜 | `muse_split.py` | 识别"一盏接一盏/依次/逐渐/然后/接着"，一条 brief 拆成多个单动作镜头 |
| ② 提示词优化 | `muse_prompt.py` | 剧情描述 → Muse 可执行提示词 + 可判定断言 |
| ③ 生成前语义验证 | `muse_verify.py` | 提示词优化后、生成前拦截丢原意/加戏；FAIL 不调用 Muse |
| ④ 素材生成 | `muse_gen.py` | 已登录 Muse 浏览器会话里生成并落盘（生成逻辑未改） |
| ⑤ 生成后自检 | `muse_qc.py` | 技术指标 + 抽帧 + 多模态判图 → PASS / PARTIAL / FAIL |
| ⑥ 角色一致性检查 | `muse_consistency.py` | 参考图与视频抽帧分别描述 → 文本比对，判跨镜同脸（可选 `--ref`） |
| ⑦ 闭环调度 | `muse_shoot.py` | 串起全链路；FAIL 时把失败原因翻译成修正要求，重写提示词重试 |
| 自检器 | `verify_muse_framework.py` | 在线 52 项 / 离线 48 项检查（含反例、模型可用性、汇总逻辑、分类统计与 5 帧口径） |

## 三、本轮新增的四项

### 1. 生成前语义验证（最省成本的一道闸）

`muse_verify.py` 把用户原句拆成原子要点，再判断改写后的提示词是否逐条覆盖：

- `entailed`：提示词里能找到对应内容
- `missing`：原句的要点丢了
- `contradicted`：提示词和原句冲突

只有全部 `entailed` 才 PASS。有缺失时输出 `retry_hint`，`muse_shoot.py` 收到 FAIL 后**直接重写提示词进入下一轮，不调用 Muse**。

实测：原句 `走廊的灯一盏接一盏熄灭` + 改写 `一只手敲了敲302的门` → FAIL，覆盖率 0%。
模型偶发无返回时回退中文片段覆盖检查，并标记为 `soft`——只记录警告，不因措辞差异误伤成硬失败。

### 2. 递进动作自动拆镜（直接解"一盏接一盏"）

`muse_split.py` 检测顺序词：
`一盏接一盏 / 一盏一盏 / 一盏盏 / 依次 / 逐个 / 一个个 / 接连 / 先后 / 逐渐 / 渐渐 / 慢慢 / 然后 / 接着`

命中后把一条 brief 拆成多个**单瞬间**镜头，每镜只写一个 5 秒内可完成的动作，形成起始态 → 中间变化 → 终态。

```
输入：走廊的灯一盏接一盏熄灭
→ S03_S01：第一盏灯熄灭
→ S03_S02：中间几盏灯相继变暗
→ S03_S03：最后一盏熄灭，走廊陷入黑暗
```

关键：**单条视频、单帧抽样都证明不了"依次"**，只有拆成多镜才能让每个瞬间可生成、可验收。

### 3. 角色一致性检查（漫剧跨镜同脸）

`muse_consistency.py` 走"分别描述 → 文本比对"的单图路径：
1. 参考图让本地多模态模型只描述外貌（脸型、发型发色、服装配色、体型、标志物）
2. 视频抽 3 帧，逐帧同样描述（这是角色一致性模块的帧数；生成后自检 `muse_qc.py` 已独立提到 5 帧）
3. 对比两组描述，输出 `same / different / unsure`

汇总：过半帧 `different` → FAIL；过半 `same` → PASS；其余 PARTIAL。
信息不足一律 `unsure`，不误伤。模型超时降级为 unsure 并写进报告，不中断流程。

**为什么不做双图同时比对**：本机多模态接口同时传两张图时返回空或 `unsure`，单图路径稳定。

### 4. 断言分类表 + 抽帧提到 5

`muse_prompt.py` 给每条断言打类别标签：`动作 / 空间 / 数量 / 色调 / 文字`，类别口径只在这一处定义，`muse_qc.py` 直接复用。

- `muse_qc.py` 默认抽帧从 3 提到 **5**（`--frames` 可覆盖），报告里列出实际逐帧结果。
- 报告末尾多一张**按类别的漏检统计表**：每类列断言数、PASS / PARTIAL / FAIL 数、**漏检率 =（PARTIAL + FAIL）/ 总数**。
- 漏检口径：非 PASS 即漏检（PARTIAL 也算），与总判定口径一致。
- 类别由断言文本关键词判定，例如「走廊」归空间、「灯熄灭」归动作、「三盏」归数量、「冷蓝」归色调、「水印」归文字。

## 四、提示词是怎么改的

对"走廊的灯一盏接一盏熄灭"这类递进句，两条路径：

**规则模式（快、稳）**：识别到"一盏接一盏"，自动压缩成
> 深夜公寓走廊。走廊的灯熄灭，从画面近处向深处一次性完成，最后完全静止。镜头固定或极缓慢推进。冷蓝色调，悬疑氛围。竖屏 9:16 构图，时长 5 秒……

并明确警告：`若要逐盏熄灭的节奏感，请拆成多镜`。

**大模型模式（`--llm`，推荐）**：本地多模态模型重写成
> 深夜旧公寓长走廊，天花板上一排六盏方形吸顶灯纵向排列。镜头缓慢前推，灯由近及远依次熄灭，5秒内全部灭完，最后只剩走廊尽头窗户透进的冷蓝微光……

同时产出能一帧判定的断言，例如：
- 画面中可见走廊天花板上一排顶灯
- 镜头推近后，画面里可见的顶灯全部处于熄灭的暗色状态，画面总体以暗部为主

关键设计：**断言必须能在提示词里找到出处**（`aligned` 标记）。模型自己加戏写出的"袖口""亮光带"之类，若视频没做到只判 PARTIAL，不误伤成硬失败。文字类负面约束自动留出门牌号例外——剧情里的 `302` 不再被误判成水印。

每条断言还带 `cat` 类别字段（动作/空间/数量/色调/文字），报告据此按类统计漏检率。

## 五、自检是怎么判的

1. **技术层**：`ffprobe` 读分辨率/时长/帧率/编码，画幅必须是竖屏，时长 1–15 秒。
2. **语义层**：从视频均匀抽 **5 帧**（默认，`--frames` 可改），逐帧喂给本地多模态模型，按断言给出 `yes / no / unsure`，并写中文依据。
3. **汇总**：
   - `must` 断言任一帧 yes → PASS；全帧 no → FAIL；其余 PARTIAL
   - `must_not` 出现 no → FAIL
   - 不同步的断言 FAIL 降为 PARTIAL
   - 总体有 FAIL → FAIL；否则有 PARTIAL → PARTIAL；全 PASS → PASS
4. 报告落盘为 `*_qc.md`，含逐条依据、实际抽帧清单、重试建议。
5. **分类统计**：每条断言按 `动作/空间/数量/色调/文字` 归类，报告末尾输出各类断言数、PASS/PARTIAL/FAIL 数与漏检率（非 PASS 即漏检）。

python muse_shoot.py --brief "走廊的灯一盏接一盏熄灭" --llm --dry-run

# 6) 完整闭环（真生成 + 自检 + 不合格重试）
"D:/muse/muse-protocol/.venv/Scripts/python.exe" muse_shoot.py \
    --brief "走廊的灯一盏接一盏熄灭" --kind video \
    --out "D:/.../S03.webm" --retries 2 --llm \
    --ref "D:/.../角色参考.png"

## 八、当前边界（如实说明）

- **单帧判不出"依次"**：多帧抽样只能验证首尾及中间若干帧的状态差异；真正的递进靠 `muse_split.py` 拆成多镜后逐镜验收。
- **本地视觉网关不稳定**：同一张图偶发 120 秒超时。模块已加重试和降级，超时判 `unsure` 并写进报告，不会误报 PASS 或中断流程。
- **角色一致性是小写检查**：比对的是"分别描述后的文本"，不是像素级人脸比对；信息不足时一律 unsure。
- 生成脚本 `muse_gen.py` 仍走浏览器/CDP 已登录会话（Muse 无官方视频 API），本轮未改动其生成逻辑。

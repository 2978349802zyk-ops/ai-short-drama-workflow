# AI 漫剧制作工作流 · 全流程总览（供外部审阅）

> 用途：把整套工作流浓缩成一份可整篇阅读的文档，交给外部 AI（Muse）审阅，请它指出还缺什么。
> 生成时间：2026-11-25。对应的完整仓库：GitHub `ai-short-drama-workflow`（163 个文件，已公开）。

---

## 一、这套工作流是干什么的

用 AI 全自动生产**竖屏短剧（漫剧）**，单人操作，从主题一句话到成片 mp4 全链路本地化：

- 剧本、分镜、提示词：本地大模型生成
- 角色定妆图 / 分镜图：四条通道按成本与一致性择优
- 每镜视频：Muse 网页自动化（带参考图锁角色）
- 配音：本机 Speech-AI-Forge（qwen3-tts，固定音色 Serena）
- 剪辑封装：ffmpeg / MoviePy 脚本

**质量目标**：对标平台爆款短剧的节奏与钩子，技术指标满足投流要求（竖屏 720×1280 / 24fps / H.264 / AAC / 响度 −16 LUFS / faststart）。

## 三、全流程 4 步（一键模板流程）

### 第 1 步：给主题 → 自动出剧本 + 分镜 + 提示词 + 定妆描述
```
drama_from_theme.py --theme "新剧主题/设定" --shots 6 --out "<剧名目录>"
```
产出 4 个文件：
- `剧本.json`——完整结构（角色 + 分镜），**单一真源**，可手改后再走下一步
- `分镜表.csv`——项目分镜格式
- `提示词库_带参考图.json`——每镜自带 ref，指向定妆图
- `角色定妆图提示词.txt`——每角色一段，喂 Muse 出定妆图

### 第 2 步：Muse 生成角色定妆图（每主角一张，全剧共用）
```
gen_looks.py --looks "<...>\角色定妆图提示词.txt" --ref-dir "<...>\定妆图"
```
产出 `定妆图\<角色名>.png`，正好是第 1 步提示词库里每镜 `ref` 指向的文件，自动对上。

### 第 3 步：批量生成视频（每镜带定妆图锁角色）
```
muse_shoot.py --briefs "<...>\提示词库_带参考图.json" --outdir "<...>\视频" ^
  --kind video --retries 1 --llm --manifest "<...>\视频\manifest.jsonl"
```
每镜自动上传对应角色定妆图当参考图，锁住人物和服装，减少漂移。

### 第 4 步：MoviePy / ffmpeg 后期成片
拼接片段 + 叠旁白 + 烧中文字幕 + 调色 + 响度归一，输出竖屏成片。

## 四、四条出图通道（开新剧先选）

| 通道 | 用什么 | 质量 | 花费 | 谁动手 | 适合 |
|---|---|---|---|---|---|
| A | WorkBuddy `hy-image-3.5` | ★★★★ 写实电影质感 | 6.57 积分/张 | 全自动 | 主力、批量出满一集 |
| B | ChatGPT 网页版 | ★★★★★ 构图光影最好 | 免费（自己账号） | 手动 | 关键镜头、最想要的那几张 |
| C | 本机 → Cloudflare FLUX | ★★★★ | 0 元，10,000 neurons/天（约 11 张） | 全自动 | 省积分补充，量小 |
| D | 本机 → Muse 网页 | ★★★★ 强在参考图锁角色 | 0 元，周额度（百分比）+ 备用词元池 | 全自动 | 人物高度一致的连续镜头 |

选法：
- 要人物绝对一致的连续镜头 → D
- 要批量出满一集 15 张 → A
- 要最漂亮的那几张 → B
- 不花积分但控量 → C（每天 11 张封顶）

**坑（已踩过）**：FLUX 额度用光会回退到 sana，sana 出的图粉衣服、无吊坠、带 pollinations 水印——**sana 已从代码里禁用，绝不能当回退**。

## 五、Muse 出片硬规则（防浪费额度，核心风控）

### 生成前三道门（任一不过 = 禁止发送）
1. **参考图合规**：只允许无人物写实锚点图（白名单写死路径）；人物穿卡其风衣的图、动漫感定妆图一律禁用；文件必须真实存在且宽度 ≥ 600px。
2. **提示词完整**：`人物外观：` 段必须存在且 ≥ 10 字；出现「动漫/二维/插画/卡通/草稿/未定妆」即拒；必须有「写实电影质感」；时长字段写 10 秒（Muse 视频固定 10 秒）；空镜不得带动作断言。
3. **Muse 页面空闲**：有输入框、无排队中任务、最近一条不能是「做好了」却无视频。

### 生成中
- **一次只发一镜**，上一镜没拿到合格成片不许发下一镜；禁止后台批量连发。
- 单镜等待上限 420 秒，超时判失败，不自动重试。

### 生成后三道验收（任一不过 = 该镜作废）
- **A 真的抓到视频元素**：`video` 元素、`videoWidth ≥ 600`、`1 ≤ duration ≤ 15`、src 不在发送前快照里。只看「做好了」文本不算成功——Muse 会回文字但不吐视频。
- **B 文件落盘且规格对**：ffprobe 校验 720×1280、时长 10.0s±0.5、大小 ≥ 1MB。
- **C 画面人眼核对**：抽开头/中间/结尾 3 帧，核对服装（米白加绒连帽睡裙）、场景（老旧公寓楼道/302 门）、有无水印字幕。

### 失败处理
- 一镜失败最多重生 1 次，且必须换条件（改提示词或换参考图），不许原样重发。
- 连续 2 镜失败 → 停整批，向用户汇报卡点，等指令。
- 每次失败记 `生产记录.jsonl`。

### 额度纪律 + 血的教训
- 每一次「发送了但没拿到成片」记 `WASTED`，当周累计超 3 次必须停下复盘；没确认前不许批量连发超 3 镜。
- **2026-11-19 事故**：S2 导出后 MD5 与 S1 完全相同——下载逻辑在「找不到指定视频」时静默回退到「时长最长的视频」，两镜都 10 秒并列第一，于是把 S1 当 S2，白烧一次额度且**表面还是 PASS**。
- 由此定死三条：① 指定了视频源必须命中那一条，找不到直接报错，绝不回退；② 生成后必须内容去重，字节相同即判 `POST_FAIL` 并删文件；③ 定位视频用**消息文字锚点**，不用 blob 地址（Muse 每次重渲染都换新 blob id）。

## 六、角色一致性方案

- 每个主角一张**定妆图**，全剧镜头共用，每镜提示词自带 `ref` 指向它。
- 提示词模板固定四段：镜头类型 / 人物外观 / 动作与场景 / 风格与画质，写实主锁写死「写实电影质感」。
- 已知边界：参考图只引导外观，不保证像素级锁死姿态与空间细节（实测门牌、侧脸仍可能漂）。

---

## 七、配音与音频规范

- 引擎：本机 Speech-AI-Forge，模型 `qwen3-tts-06cv`，音色固定 `Serena`，温度 0.55、top_p 0.85、speed 0.95、固定 seed 42 保证可复现。
- **数字读法铁律**：字幕写阿拉伯数字，送 TTS 的文本必须写汉字。例：「302」字幕写作 `302`，TTS 文本写 `三零二`（实测「三零二」2.25s vs「三百零二」3.01s，差一个音节）。
- 每条配音生成后裁静音 + atempo 变速贴合镜头时长。
- 混音链：`compand`（不用 acompressor）→ `alimiter`（limit 0.85）→ 响度归一到 −16±2 LUFS，真峰值必须为负。
- 响度二次处理**必须从原始 wav 母版重做**，不能拿已归一化的成片再压。
- 已知缺陷：该 TTS 模型输出自带 4–8 kHz 宽带嘶声（分层渲染证实比音效层/BGM 层高 26 dB），RNNoise 实测只能降 1–2 dB 无效；暂用「音效高频滤波 + 母版 afftdn + 15k 低切」压制，未彻底解决。

## 八、成片技术规格（硬指标）

- 分辨率 720×1280（9:16 竖屏），24fps，H.264，`yuv420p`，crf 18–19，`+faststart`
- 音频 AAC 192kbps / 44.1kHz / 单声道
- 响度 −16±2 LUFS，真峰值 < 0 dBFS
- 交付前必做：`ffprobe` 校验参数、全片解码 0 错误、faststart 标志为 true、抽帧核字幕无乱码
- 中文字幕烧录四个硬坑已记录：`fontfile` 不能带 `C:`、`sine`/`anoisesrc` 必须走 `-f lavfi -i`、路径必须转义、字号按 720 宽换算

## 十一、已知缺口（请重点给建议的部分）

1. **内容层面**：怎么把 15 秒钩子做到爆款水准？前 3 秒留人、7 秒反转、结尾断点，有没有可复用的结构模板？
2. **节奏层面**：28 镜 100 秒平均 3.57s/镜，是否偏慢？短剧常见的 1.5–2.5s 快切该怎么排？
3. **一致性层面**：定妆图锁角色仍会漂（门牌、侧脸）。除了参考图，还有什么工业做法（多参考图、关键帧回填、首尾帧约束）？
4. **声音层面**：TTS 自带 4–8 kHz 嘶声，RNNoise 无效，是否有更好的开源降噪/换模型方案？
5. **配音表演**：单音色单情绪，缺少情绪变化。短剧配音该怎么分情绪、怎么切句？
6. **流程层面**：这套 4 步流程还缺哪些环节（比如选题验证、封面/标题、投放复盘回流）？
7. **成本层面**：单集 28 镜 × 10 秒视频，词元消耗偏大，有没有降本路线（减少镜数用长镜、复用镜头、静帧推拉）？
